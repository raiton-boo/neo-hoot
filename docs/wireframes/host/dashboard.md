# ホスト: クイズ一覧画面 (`dashboard.html`)

## 共通ヘッダーの導入

ログイン前（`login.html`）の巨大な「neo-hoot」ロゴ（`h1`, 2.5rem）と、ログイン後の画面見出しが同じ見た目だと、内部ページなのに毎回ランディングページのような印象になってしまう（違和感の原因だった）。これを解消するため、ログイン後の管理画面系には**小さめの共通ヘッダー**（`.app-header`: ロゴ＋ユーザーメニュー）を導入し、ページごとの見出し（「クイズ一覧」等）は通常サイズにする。

どの画面に共通ヘッダーを入れるかの方針は`docs/design.md`を参照（管理画面系のみ、ライブ進行画面には入れない）。

## 見出しの命名

「マイクイズ」は却下し、「クイズ一覧」に変更した。より落ち着いた命名。

## 「＋ 新しいクイズを作成」の重複を解消

見出し横のボタンと、カード一覧末尾の「追加」タイル（半透明で分かりにくかった）が重複していたため、見出し横のボタン1つに統一した。

## クイズカードのグリッド幅

`grid-template-columns: repeat(auto-fill, minmax(220px, 1fr))`の`220px`だと、カード内の「開催回数」バッジと「開催する」ボタンが横に並びきらずレイアウトが崩れていた。`320px`に広げて解消した。

## ユーザーメニュー

アバター＋名前＋シェブロン（▼）アイコンをまとめて1つのクリック可能なボタンにする（`.app-header .user-menu`）。

### 開き方: PC/スマートフォンで変える

- **PC**: ボタンのすぐ下にドロップダウンパネル（`.user-menu-panel`）が出る。ホバーではなくクリックで開閉する（ホバー式だとカーソルが少しズレただけで閉じてしまい、誤操作が起きやすいため）。
- **スマートフォン**（`max-width: 640px`）: 画面下からせり上がる「ボトムシート」形式に切り替わる。背景を半透明の暗いオーバーレイ（`.user-menu-overlay`）で覆い、シート外側のタップで閉じられるようにする。指でタップする操作ではドロップダウンよりボトムシートの方が押しやすく、片手操作にも向いているため。
- 実装（`apps/web`）では、開閉状態はReactの状態（`useState`）で管理し、`.user-menu-panel`/`.user-menu-overlay`の表示・非表示を切り替える。CSSのメディアクエリ自体は変更せず、同じマークアップがPC/スマートフォンで見た目だけ変わる。

### メニューの中身

- 上部: アバター＋名前＋メールアドレス（今ログインしているアカウントの確認用）
- 「ログアウト」
- 「アカウント削除」（`--color-danger`で強調。取り消せない操作のため、実際に押すと確認ダイアログを挟む。`docs/spec.md`の「アカウント削除の確認」を参照）

## クイズの削除は「アーカイブ」方式にする

`docs/er.md`の「削除時の連鎖動作」の通り、一度でも開催したクイズはDB制約で完全削除ができない。これをUI側でも一貫させるため、通常の削除操作は「アーカイブする」（一覧から見えなくするだけで、データは残す）という形にした。詳細は`docs/wireframes/host/archived-quizzes.md`を参照。

- 一覧に「開催回数: 0回」のクイズ（未開催）も1件追加し、アーカイブ対象がどちらのケースでも同じ「アーカイブする」ボタン1つで統一されていることを示した

### アーカイブ済み一覧は別ページにする

「アーカイブ済みも表示する」チェックボックスで同じ一覧に混ぜる案、`.mode-switch`のタブで切り替える案の両方を試したが、どちらも「普段使うクイズ」と「もう使わないクイズ」を同じ一覧の中で扱おうとして、並び順やグルーピングのロジックが余計に複雑になっていた。`login.html`→`dashboard.html`のように、**画面ごとに別ページとして完結させる**という今までの作り方に合わせ、`archived-quizzes.html`という独立したページに分けた。見出し横に「🗄 アーカイブ済みを見る(N)」という、他の画面遷移と同じ普通のリンクを1つ置くだけにしている。Next.js実装時も、単純に別ルート（例: `/dashboard/archived`）を追加するだけで済む。

### 編集・アーカイブのボタン: 「⋮」メニュー

カード右上に常時表示するアイコンボタン2つ（✎/🗄）を並べる案も試したが、「アーカイブする」は他の操作ボタン（開催する等）と違って取り消しにくい操作ではないものの、うっかり押しやすい場所には置きたくなかったため、「⋮」ボタンを押して初めて選択肢が見える方式にした。以前（地のテキストが並ぶだけの素朴なメニュー）からデザインを作り込み、`.card`と同じ「太枠＋オフセット影」のボックス、アイコン＋文字の各項目、1行ごとの区切り線、ホバーでの背景色変化を追加している。

### アーカイブ時のアニメーション

「アーカイブする」を押すと、カードが縮みながらフェードアウトしてから一覧から消える（`.archiving`クラス＋`animationend`イベントでDOMから削除）。何の演出もなく突然カードが消えると、今の操作で本当にアーカイブされたのかが分かりにくいため、操作の結果が画面に反映されたことを視覚的に示す。
