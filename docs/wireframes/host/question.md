# ホスト: 出題進行画面 (`question.html`)

プロジェクター等に投影する、ライブ進行画面の1つ。共通ヘッダーは含まない。

## 出題中と結果表示を1画面に統合

当初「出題進行画面」と「設問結果画面」を別々のファイル（別ページ）として作っていたが、結果表示への遷移はホストの操作を介さず自動的に起こるため、**別ページへのナビゲーションではなく、同じ画面の中の「状態変化」として扱う**ことにした。

- `question-result.html`は廃止し、`question.html`に統合した。
- `<body data-state="asking">` / `data-state="results"` で状態を切り替え、CSSで`.view-asking` / `.view-results`の表示・非表示を制御する。
- 本実装（Next.js）でも、これは別ルートではなく**1つのコンポーネントが持つ2つの状態**として実装する。

## ヘッダーのバッジ

- 「第2問/全5問」「回答済み」の2つは、離れた四隅ではなく、**タイマーを挟んで中央にまとめて配置**する。プロジェクター視聴時、視線が集まる中央から離れた隅は見落とされやすいため。
- 見た目は白背景（`--color-surface`）の枠付きピル型バッジに統一する。絵文字は付けない。
- 「回答済み」バッジは文字のみとする。プログレスバーを添える案も試したが、同じ画面にタイマーがすでにあり情報過多になるため、シンプルな文字表示に戻した。

## タイマーの緊急演出

残り時間が5秒以下になったら、タイマーの背景を赤（`--color-danger`）に変える。

## 設問数の視覚化

「第2問/全5問」というテキストに加えて、`●●○○○`のようなドット表示を添え、進み具合を一目で分かるようにする。

## 選択肢の登場アニメーション

設問が切り替わった瞬間、4つの選択肢を時間差（0.1秒刻み）でポップインさせる。

## ホストの操作ボタン

| ボタン           | 表示される状態          | 役割                                                                                   |
| :--------------- | :---------------------- | :------------------------------------------------------------------------------------- |
| 一時停止/再開    | 出題中・結果表示中 両方 | タイマーを止める（技術トラブル時や補足説明用）。同じ一時停止状態を両方の画面で共有する |
| 結果を今すぐ見る | 出題中                  | 制限時間を待たず、ホストの判断で今すぐ結果表示に進む                                   |
| 次の問題へ       | 結果表示中              | 自動進行（5秒後）を待たず、今すぐ次の設問に進む                                        |
| 中断する         | 出題中・結果表示中 両方 | セッションを終了する                                                                   |

**「前の設問に戻る」ボタンは意図的に用意しない。** 一度確定した結果を覆せてしまうと、不正やルールの混乱の元になるため。

## 結果表示への自動遷移

以下の**どちらか早い方**で、出題中→結果表示へ自動的に切り替わる。

1. 制限時間が0秒になる
2. **参加者全員が回答し終わる**（制限時間が残っていても進む）

2の判定に使う「全員」の人数は、**接続が切れた参加者を除外して数える**。切断した参加者を人数に含めたままだと、その人が戻ってこない限り「全員回答済み」の条件が永遠に満たされず、他の全員が待たされ続けてしまうため。専用の「退出する」ボタンは用意しない（ブラウザを閉じる＝Socket.io接続が切れる、という同じ扱いでよい）。

## 結果表示から次の設問までの待機時間

**システム全体の固定値（5秒）とする。** クイズ作成時にホストが自由に設定できるようにする案もあったが、設定項目を増やすメリットより、シンプルさを優先した。

## 正解の表示

正解は`badge`ではなく、**元の選択肢と同じ色のバッジ**で表示する（例: 正解が選択肢Aだった場合、選択肢Aと同じピンク色のバッジで「▲ 北海道」と表示）。単なる黄色バッジだと、どの選択肢が正解だったかが色から分からないため。

一方、**個々の選択肢ラベル（北海道・岩手県...）や回答分布バーの色は、選択肢固有の色に合わせない**。バーの色は「緑＝正解」「赤＝不正解」という別の意味体系で塗り分けており、ここにさらに選択肢固有の色を重ねると、1つの要素に2つの異なる色の意味が同時に乗ってしまい、かえって分かりにくくなる。正解バッジ1箇所だけで元の選択肢との対応を示せば十分。

## 回答分布バーのパーセント表示

パーセント・人数の表示は、**バーの中ではなくバーの外側に固定表示**する。当初バーの中に表示していたが、割合が低い場合（例: 1%）にバーが細すぎて文字が隠れてしまう問題があったため。

## 制限時間が0秒になったときの挙動

1. **参加者側**: 0秒になった瞬間、回答ボタンを即座に無効化する。以降の回答送信は受け付けない。
2. **未回答の参加者**: その設問については0点として扱う（`docs/architecture.md`の採点ロジックに従う）。
3. **ホスト側**: 上記「結果表示への自動遷移」の通り、自動的に結果表示状態へ切り替わる。
