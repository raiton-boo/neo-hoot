# ホスト: ロビー画面 (`lobby.html`)

プロジェクター等に投影する、ライブ進行画面の1つ。`docs/design.md`の方針により共通ヘッダー（`.app-header`）は含まない。

## ルームコード＋QRコードの表示

- ルームコードとQRコードは、別々の要素ではなく**1枚のカードにまとめて「セット」**であることを示す（`.room-qr-card`）。
- QRコードは`neo-hoot.app/join`のような汎用ページではなく、**このルーム（ルームコード）に直接紐づくURL**（`?room=xxxx`付き）を指す。参加者がスキャンすると、参加画面のルームコード欄に自動入力される（`participant/join.html`側の実装と対応）。
- QRコードの枠は、ボタンのような「影付き」にはしない。ルームコード表示と同じ「枠のみ・白背景」に揃え、余白（`padding`）を十分に取ることで視認性を確保する。
- QRコード画像の読み込み中はスピナーを表示し、読み込み完了後に画像を表示する（`#qr-spinner` / `#qr-img`のloadイベント）。

## 参加者一覧のレイアウト

- チップは**固定幅（100px）・固定ギャップ（0.75rem/12px）**で、ちょうど10個分の幅（`1108px`）にコンテナの`max-width`を制限し、それを超えたら自然に折り返す。「10人ごとに1行」で揃える。
  - CSS Gridで「常に10列」にする方式も試したが、参加者が少ない時に余白が広がりすぎる問題があったため、固定幅チップ＋コンテナ幅制限のFlexboxに変更した。
- **長い名前**は折り返さず、`text-overflow: ellipsis`で省略する（チップの高さを常に一定に保つため）。省略時は`title`属性でフルネームを保持し、ホバー/長押しで確認できる。

## 参加者チップの「接続中→参加確定」2段階アニメーション

参加者が入ってきた瞬間にいきなり名前入りチップが出現すると唐突なため、以下の2段階にする。

1. **接続中**: 名前が確定する前に、中身のないプレースホルダーを薄く点滅させる（`.participant-chip.connecting`）
2. **参加確定**: 名前が確定した時点で、プレースホルダーを実際の名前に差し替え、ポップイン（拡大しながらフェードイン）させる（`.chip-pop-in`）

### Socket.ioでの実装方針

- **接続中**: 参加者クライアントが`join-room`イベントを送った直後、サーバーの検証・DB保存が終わる前に、`participant:connecting`のようなイベントをホストへブロードキャストする。
- **参加確定**: サーバー側で`Participant`レコードの保存が完了した時点で、`participant:joined`イベント（確定した名前を含む）をホストへブロードキャストする。
- **複数人が同時に参加した場合**: Socket.io自体がタイミングを調整するわけではなく、各参加者は独立したイベントとして扱われる。フロントエンドが**参加者IDをキーにしてチップを管理**すれば（名前ではなくID基準にする）、同時に何人参加しても取り違えは起きない。特別な同時参加対応ロジックは不要。
- **注意**: ローカルネットワークでは接続からDB保存までが一瞬で終わるため、「接続中」状態がほとんど見えない可能性がある。体感できるアニメーションにしたい場合は、「接続中」状態を意図的に一定時間（例: 300〜500ms）表示し続けるUI側の最低表示時間を設ける手法も検討する。
